# Voice Mail Android app

Original Android application for Mint's existing carrier voicemail mailbox. It authenticates over Mint cellular data, displays the actual inbox, downloads recordings privately, and plays them through Android's native player. Samsung Phone remains the default dialer. The app has no carrier privileges. Connection and uncached downloads need network access; cached audio and generated text remain available offline. Contacts access is optional for caller-name lookup and search.

View the [screenshot gallery](../README.md#screenshots) for the inbox, player, settings, themes, and tutorial. Caller details are hidden in the documentation images.

The app icon combines voicemail reels with a mint speech bubble on a deep-green background. Adaptive launcher layers support device masks; Android 13+ receives an explicit monochrome layer for themed icons. The notification symbol uses the same mark. [Branding assets and native previews](../docs/branding/README.md).

Build with Python 3.11+ and Java 17+:

```sh
python probe/bootstrap.py
python probe/build.py --module app
```

The verified debug APK is `app/build/visual-voice-mail.apk`. The app uses its own package (`org.visualvoicemail.app`) and generated debug signing key, separate from the diagnostic probe. CI builds and verifies both modules. The app build downloads checksum-pinned sherpa-onnx 2.0.1 and Kotlin 2.2.0 artifacts from their official release hosts. Native libraries support arm64-v8a phones and x86_64 emulators, with 16 KB ELF load alignment. Models are downloaded on the phone, separately from the APK.

For a signed, non-debuggable APK use `python probe/build.py --module app --release` with the existing local release-signing configuration. First-time signing setup, identity backup, and development-to-release upgrade behavior are documented in [release instructions](../docs/releases.md). Signed downloads live in [GitHub Releases](https://github.com/5ham5h33r/visual-voicemail/releases).

Authentication establishes an independent service instance and retrieves a service-instance token. The carrier mailbox interface requires its public `VVMOTT` profile/version headers, a subscriber `tel:` URI, and an encoded bearer token. These are protocol fields, not an official signing identity or an extracted credential. The app's User-Agent identifies this project.

Mailbox credentials and the inbox are persisted with authenticated AES-GCM encryption using a key held in Android Keystore. On reopening, the saved inbox appears immediately and downloaded recordings can play from app-private storage. A valid restored token can refresh the mailbox over Wi-Fi; initial authentication or renewal still needs Mint cellular data. Tokens and subscriber identifiers are never written to diagnostic output or sent to a project server.

Open the top-right Settings gear for appearance, contact names, message order, playback, sync, storage, privacy, permissions, and app information. Theme offers Use device setting, Light, Dark, and AMOLED (true black). AMOLED uses pure-black backgrounds with grouped dark cards. The recording detail player supports seeking, adjustable skip intervals, playback speed, and device/speaker/earpiece output choices. It displays the active audio route. Playback pauses when leaving the app and never automatically resumes on return. Opening a message reveals its player and transcript. See [Settings](../docs/settings.md) for options and validation.

The top-left carrier label uses the default mobile-data SIM's service-provider name and refreshes when returning to the inbox. It falls back to Mint Mobile when SIM information is unavailable. This display requires no new permission; the mailbox backend remains Mint-only. See [SIM carrier label](../docs/sim-carrier-label.md).

Welcome offers Get Started directly into the inbox or Show me around for four optional introduction/setup screens and spotlights on the real controls. The setup screen requests Contacts or notifications only after their Enable action. Examples are labeled and do not alter real messages. Replay from **Settings → Help & tutorial → App tutorial**. See [tutorial behavior and validation](../docs/tutorial.md).

Search filters the cached inbox by contact name, full/partial phone number, displayed or ISO date, and generated original/English text, with All, Unread, and Saved filters. Enable Settings → Contact names for local name lookup with Android's Contacts permission. Declining access keeps number/date search and playback available; names can also be turned off inside the app. Only numbers in the inbox are looked up, on a separate worker; matched names stay in memory and are not uploaded or saved in the inbox cache. Message and bulk actions offer carrier-confirmed read/unread updates, transcription, and carrier deletion after a verified durable local copy. Removed carrier messages remain in Saved; removing the local copy is a separate action. Legacy deletion marks never automatically remove carrier messages. See [carrier deletion](../docs/carrier-deletion.md) and [search actions](../docs/search-actions.md).

Choose **Settings → Storage → Download location** for exported audio. The system folder picker grants access only to the selected folder and remembers it across app restarts. Export writes a separate AMR/AMR-WB file with a date-based, unique filename. Playback and app-private Saved recordings are independent of this setting. Changing or forgetting the folder keeps existing exports, and Clear playback cache protects Saved recordings and exported files. Uninstalling removes app-private recordings and transcripts; export anything that must survive independently. No broad storage permission is required. Other apps with access to the selected folder can open exports.

Enable **Settings → Notifications → New voicemail alerts** for background mailbox checks and a notification when new unread messages are discovered. The default interval is about 15 minutes, with 30/60-minute choices; Android can delay checks. The app asks for notification permission, offers Android channel controls and a labeled test, and keeps caller details out of alerts. Tapping an alert opens the unread inbox. Checks retrieve metadata, without downloading audio, and survive ordinary process exit. Force-stop pauses checks until reopening. See [notification behavior and validation limits](../docs/notifications.md).

Recordings are cached privately using atomic writes. Transcription runs locally using Whisper and Silero VAD after an optional Standard (Tiny, 104 MB), Enhanced (Base, 161 MB), or Highest quality (full Large v3 int8, 1.78 GB) download. Tiny/Base are English-only; Large enables other languages and separate English translation. Downloads retain partial progress and verify pinned hashes before use. Transcripts are encrypted at rest, searchable offline, and provide approximate phrase-based playback anchors. [Implementation and validation](../docs/transcription.md). Settings also includes local greeting recording/import, preview, and explicitly confirmed carrier saving; the active live greeting has not been replaced in testing. No forwarding or PIN changes are implemented. Direct standalone push delivery remains unverified.

Transcription quality is available in Settings and beside the recording's Transcript heading, with an adaptive stacked layout for larger text. Search is a direct icon on that heading row. Plain-language quality choices include the model name, explain speed/storage, and retain existing transcripts until Update transcript is selected. Shared tap feedback covers buttons, icons, inbox rows, settings, transcript phrases, and dialog actions; Reduce motion and Android animation settings are respected. Optional Mark as read when playback starts is off by default and requires a confirmed update. See [motion behavior](../docs/motion.md) and the [final UX review](../docs/ux-final-review.md).
