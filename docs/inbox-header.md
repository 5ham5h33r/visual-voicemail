# Scrolling inbox header in version 0.18

The persistent offline footer is removed. At the top of a short inbox, the carrier label, large title, status, search field, filters, and Select/Refresh row remain easy to reach. With a longer inbox, that content scrolls away with the messages. A compact toolbar retains the page title, mailbox status, search, filters/inbox actions, and Settings. Returning to the top restores the expanded header.

This follows the extended/condensed app-bar pattern in [Samsung's One UI guidance](https://developer.samsung.com/one-ui/comp/app-bar.html), while retaining the existing app typography and colors. The expanded title crossfades into the compact one as the user scrolls. There is one native ScrollView, so drag, fling, reverse scrolling, focus, and accessibility scrolling share the same coordinate space. Scrolling does not alter the expanded header's measured height, avoiding layout/scroll feedback and jumps. Short lists do not get artificial blank content to force a collapse.

The compact search action brings the real search field into view and opens the keyboard. The filter menu provides All, Unread, Marked, Select messages, and Refresh/Connect; the title identifies an active Unread or Marked filter. Selection uses a compact action header and closes the keyboard. It preserves list-relative position when entering/leaving selection. Notification entry and the anchored tutorial leave selection before showing the relevant controls.

The scroll offset and selection return behavior are saved across recreation. Returning from Settings keeps the same position. Explicit filter changes, restoration, and the tutorial stop existing native fling momentum before positioning content. Reduce motion (or Android's disabled-animation state) removes the crossfade; direct finger-driven scrolling remains native. Touch targets stay at least 48 dp, and the compact title/status container can grow with font scaling.

Validation uses synthetic long/short inboxes and actual phone gestures without carrier writes or personal audio. Cases cover partial/full title transitions, stable header measurements, pinned toolbar position, native swipe/fling, compact filtering/search, keyboard visibility, selection position, Back, recreation, returning from Settings, and reduced motion. Light, Dark, and AMOLED screenshots were reviewed after caller/date/transcript details were hidden. Broader large-font, landscape, and TalkBack traversal coverage remains open; no device display, font, rotation, or animation settings were changed.

The S24 Ultra passed 38 header checks, plus 32 onboarding, 42 bulk-action, 33 navigation, 28 quality/motion, and 14 recording checks (187 total). All 86 host behavior checks and theme contrast checks passed. Fixtures were view-only and original app preferences were restored.

Version 0.19 shows the search clear button only while the field contains text, including whitespace. Clearing retains search focus and hides the button again. Initial visibility also follows a restored query. The existing 38 header checks passed, and empty/typed/cleared/whitespace behavior was checked directly on the S24 Ultra.

Version 0.22 coordinates selection-mode header collapse/expansion and list movement over 220 ms, rather than instantly hiding the header before fading the toolbar. Ordinary finger-driven inbox scrolling still keeps a stable header height. See [motion](motion.md).
